# LEO AI — NVIDIA-style Frontend

Build a complete NVIDIA-inspired frontend on top of your existing LEO AI backend. **No backend changes.** The frontend will call your existing endpoints (`/v1/chat/completions`, `/v1/embeddings`, `/api/v1/leo/*`, memory, KG, metrics, security) using the JWT Bearer flow you already have.

## Design system (NVIDIA-inspired)

- **Palette**: Deep black `#000000` / near-black `#0A0A0A` surfaces, white text, signature NVIDIA green `#76B900` as the single accent (CTAs, hover, active state, data highlights). Subtle graphite borders `#1F1F1F`.
- **Typography**: NVIDIA Sans style stack — `Inter` for body, `Space Grotesk` (bold/black weights) for hero + section titles. Tight tracking, oversized headlines (72–120px on desktop).
- **Motion**: Restrained. Hover lifts on cards, green underline sweeps on nav, subtle fade-up on scroll. No fade-in on every element.
- **Layout language**: Full-bleed dark sections, edge-to-edge hero media, dense product-grid cards with corner-cut/sharp radii, right-aligned chevron CTAs ("Learn more ›"), thin uppercase eyebrow labels.
- All tokens go in `src/styles.css` under `@theme inline` (green, surface tiers, borders, shadows). No hardcoded hex in components.

## Sitemap (TanStack routes)

Public marketing:

- `/` — hero (LEO AI on commodity hardware), stat strip (99.3% compute avoided, 490kW saved, 1.72M requests), 3 pillar cards (Local-first, CPU+iGPU, Semantic Memory), tech showcase, CTA.
- `/platform` — architecture: Phi-3 router → GraphRAG / Mistral path, OpenVINO, GGUF mmap, speculative decoding.
- `/features` — grid of all capabilities (LLM inference, multi-model routing, semantic cache, KG, benchmarks, document understanding, code assist, plugins).
- `/benchmarks` — live pull from `GET /api/v1/leo/metrics` with big-number cards + chart.
- `/docs` — links + embedded overview of your 3 API docs; endpoint reference table.
- `/about` — vision, solo-dev story.
- `/pricing` or `/download` — CTA to get LEO AI.

Auth:

- `/login`, `/signup` — email + password → POST to your auth endpoint, stores JWT in `localStorage` + auth context. `/forgot-password` optional.

App (gated under `_authenticated/`):

- `/app` — dashboard: live metrics tiles, recent orchestrations, model router status.
- `/app/chat` — OpenAI-compatible chat UI (AI Elements: Conversation, Message, PromptInput, Shimmer) calling `POST /v1/chat/completions`, streams tokens, renders `x_leo_metadata` (resolved_by, latency_ms, compute_avoided, gpu_watts_saved) inline under each assistant reply.
- `/app/orchestrate` — advanced form hitting `/api/v1/leo/orchestrate`, shows routing path (Router → GraphRAG or Mistral) as a visual timeline.
- `/app/memory` — list/create memories across types (episodic|semantic|working|reflection|failure|procedural).
- `/app/knowledge-graph` — entity/relationship browser, 2-hop query panel.
- `/app/embeddings` — text → 384-dim vector playground.
- `/app/benchmarks` — deeper metrics + history.
- `/app/security` — JWT/RBAC info, rate-limit status.
- `/app/settings` — API base URL, token, model preferences.

## Backend wiring (zero backend changes)

- Add `VITE_LEO_API_BASE_URL` (default `http://localhost:8000`) in `.env` for local dev; expose an in-app setting on `/app/settings` so users can point at any deployment.
- `src/lib/leo-client.ts` — thin fetch wrapper: attaches `Authorization: Bearer <jwt>`, handles 401 → redirect to `/login`, respects rate limits (surfaces 429 as toast), streams SSE for chat completions.
- `src/lib/auth-context.tsx` — React context storing `{ token, user, permissions }`. TanStack Router `createRootRouteWithContext<{ auth }>` gate on `_authenticated`.
- TanStack Query for all reads (`ensureQueryData` in loaders, `useSuspenseQuery` in components) — matches your endpoint list 1:1.
- Typed endpoint modules: `src/lib/api/{chat,embeddings,orchestrate,memory,kg,metrics,security}.ts`, generated by hand from your OpenAPI spec shape.

## AI Elements chat surface

- Install: `conversation`, `message`, `prompt-input`, `shimmer`, `tool`, `response`.
- Assistant messages: no background, plain foreground on black. User messages: `bg-primary` (LEO green) with `primary-foreground` black text — verified contrast.
- `x_leo_metadata` rendered as a collapsed `<Tool>` accordion under each reply: shows resolved_by, latency, compute_avoided badge, watts saved.
- Empty-state uses a generated LEO wordmark, **not** the Sparkles icon.

## Head metadata & SEO

Every route defines its own `head()` with unique title, description, og:title, og:description. Leaf routes with hero imagery add og:image. Root sets font `<link>` (Inter + Space Grotesk from Google Fonts) — never `@import` in CSS.

## Build order

1. Design tokens + fonts + Nav/Footer shell in `__root.tsx`.
2. Marketing routes (`/`, `/platform`, `/features`, `/benchmarks`, `/docs`, `/about`).
3. `leo-client.ts` + auth context + `/login`, `/signup`.
4. `_authenticated` gate + app shell + sidebar.
5. Chat (AI Elements) → Orchestrate → Metrics → Memory → KG → Embeddings → Security → Settings.
6. Polish: motion, empty states, error/loading, 404.

## Assumptions (confirm if wrong)

- Backend runs at `http://localhost:8000` during development; the frontend needs no proxy — it calls the base URL directly with the JWT.
- Your auth endpoint that mints the JWT is reachable from the browser (e.g. `POST /v1/auth/login`). If the exact path differs, I'll adjust `login.tsx` when you share it.
- No Lovable Cloud/Supabase — auth and data live entirely in your Python backend.
